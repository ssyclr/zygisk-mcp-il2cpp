这是面向自有或已获授权 Android 应用的运行时调试工具，支持 Unity IL2CPP、Unreal 和原生程序。既可以在游戏内使用悬浮工作台，也可以连接 MCP，让 AI 查询、分析和执行经确认的调试操作。

项目主体不公开源码，公开内容为版本说明和部分使用文档。请使用正式发布的模块安装包。

## 安装与开始使用

1. 在 Magisk／KernelSU 管理器中安装发布的模块 ZIP，按安装提示重启设备。
2. 打开模块 Web 菜单，在「目标设置」添加需要调试的包名。
3. 如只处理某个子进程，填写完整的 `包名:子进程名`；不带冒号的包名会匹配主进程及其子进程。
4. 按需设置延迟启动、悬浮窗和内存后端，保存后彻底结束并重新启动目标应用。
5. 在「MCP 连接」查看在线进程，复制连接配置，或导出 `MCP.zip` 使用 Python 连接。
6. 通过悬浮窗操作，或让 AI 先确认当前进程与可用能力，再进行查询和调试。

升级保留原有安装 ID、包名设置、连接配置和数据目录。修改监听地址或端口后需要重启设备；只修改目标配置时，重新启动目标应用即可。

## MCP 连接

推荐在 Web「MCP 连接」复制当前设备的配置，不必手填局域网地址或端口。控制端口默认 `27184`。

- **原生 HTTP**：不需要 Python。设备本机使用 `http://127.0.0.1:27184/mcp`；局域网使用手机当前地址。
- **局域网监听**：在 Web 设置为 `0.0.0.0`，保存并重启设备。`0.0.0.0` 是监听设置，不是客户端填写的连接地址。
- **Python**：从 Web 导出 `MCP.zip`，按压缩包说明配置；设备本机运行可选择直连模式，不需要 ADB 转发。
- **鉴权**：默认使用 Bearer 令牌。可手动选择无需鉴权，但任何能访问端口的设备都可能执行已开启的工具，务必仅在可信环境使用。
- **多个目标**：用 `process_list` 查看、`process_select` 选择、`process_current` 确认。目标重启后需要重新选择，不能复用旧地址。

HTTP 和 Python 使用一致的具名工具与功能开关。更新模块后，也请更新导出的客户端文件并重新连接。完整说明见 [MCP 使用文档](mcp/README.md)。

## 悬浮工作台

列表支持上下滑动，明确支持横向滚动的列表、路径和页签可左右滑动；不会因为长文本溢出而横移整个页面。调色盘、滑块和窗口缩放保留各自拖动操作。语言、主题、缩放、透明度、Toast 和布局自动保存。

Web 关闭「注入 ImGui 窗口」后，下次启动不显示悬浮窗及屏幕渲染，MCP 和原生调试仍可使用。临时隐藏窗口与关闭显示层是不同操作。

## 日志、导出与设置

- Web「运行日志」可以查看、筛选、导出与清理历史记录。日志不会因目标崩溃或重新启动自动清空。
- Dump 和资源导出写入目标应用的私有目录；MCP 返回完成状态、路径和数量，不直接返回全部正文。
- 语言、主题、分页、Toast 和窗口布局自动保存；不会自动恢复旧对象地址、断点、Hook 或上次的游戏写入。
- 内存默认使用 KittyMemory。外部驱动是否可用取决于设备、权限与协议，失败时会显示原因。
- 普通 IL2CPP 优先自动识别；特殊目标可使用已确认的符号覆盖配置，不保证解密或支持任意修改版本。
